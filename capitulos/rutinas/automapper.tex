\section{Automaper} 

Source code: \href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/automaper.py}{automaper.py}.

\texttt{automaper.py} provides a set of utilities for loading, interpreting, visualizing, and managing photonic chip layouts described through an Excel-based chip map.

The module acts as an intermediate layer between the logical description of a photonic chip and the measurement software responsible for its physical characterization. Instead of hardcoding device coordinates, port locations, or measurement combinations in Python, the chip structure is defined externally in an Excel workbook. Automaper parses this information and converts it into structured Python data models that can be used by the positioning and measurement routines.

The general workflow is:

\begin{verbatim}
Excel chip map
      ↓
AUTOMAPER
      ↓
Chip data model
      ↓
Measurement paths
      ↓
Measurement plan
      ↓
Positioning / measurement software
\end{verbatim}

The main purpose of automaper.py is therefore measurement-plan generation and management, rather than direct hardware control. The module does not move the positioning stages, acquire optical power, or execute the measurements itself. Instead, it produces the structured information required by other parts of the characterization software to perform these operations.

\subsection{Building blocks}

Automaper can be divided into three functional blocks:

\begin{enumerate}
    \item \textbf{Chip representation:} Loads the device and port definitions from the Excel workbook and converts them into the internal \texttt{chip} data structure.
    \item \textbf{Measurement-path management:} Defines the possible input-to-output connections and allows the user to enable or disable individual measurement paths through the \newline \texttt{MeasurementPaths} worksheet.
    \item \textbf{Measurement-plan generation:} Combines the chip topology with the enabled measurement paths and optional coupling constraints to generate the final \texttt{measurement\_plan}.
\end{enumerate}

The principal data structures generated by the module are therefore:

\begin{itemize}
    \item chip
    \item measurement\_paths
    \item measurement\_plan
\end{itemize}

These structures represent progressively more specific levels of information, from the physical description of the chip to the exact measurements that should be executed.

\subsubsection{Devices worksheet}
% ===========================================

The \texttt{Devices} worksheet defines the photonic devices available for characterization. Each row represents a device present on the chip and provides the information required to identify it, classify its type, document its purpose, and determine whether it should be included in the current measurement routine.

The worksheet contains four main columns: \texttt{Device}, \texttt{Type}, \texttt{Description}, and \texttt{Measure}. Their purpose is described below.

\begin{figure}[H]
    \centering
    \includegraphics[width=1\textwidth]{Routines/Automaper/AutomaperDevices.png}
    \caption{Example of the Devices worksheet used by automaper. Each row represents a photonic device and contains its unique identifier, device type, optional description, and measurement-enable status. The Device identifier is used to associate the device with its corresponding ports and measurement paths, while the Measure field determines whether the device is included in the current measurement routine.}
    \label{fig:AutomaperDevices}
\end{figure}

\begin{itemize}
    \item \textbf{Device:} This column contains an unique identifier assigned to each device. This identifier is used throughout the workbook to establish the relationship between a device and its corresponding ports and measurement paths. The identifier should therefore remain consistent across all worksheets.
    \item \textbf{Type:} This column specifies the type of the photonic device. This can be used for device-specific filtering, reporting, or future measurement and analysis routines.
    \item \textbf{Description:} This column provides an optional human-readable description of the device. This field is intended primarily for documentation and traceability. It allows the user to provide additional context without affecting the identification or measurement configuration of the device.
    \item \textbf{Measure:} This column determines whether the device is enabled for the current measurement routine. When a device is disabled, all measurement paths associated with that device are excluded from the generated measurement plan. This allows the user to remove an entire device from the current characterization routine without modifying its individual measurement paths.
\end{itemize}


% ===========================================
\subsubsection{Ports worksheet}
% ===========================================

The Ports worksheet defines the optical ports associated with each device and provides the physical information required to locate and characterize them. Each row represents a single port and establishes its relationship with a device through the Device identifier.

In addition to identifying the port, the worksheet specifies its direction, physical coordinates, and coupling configuration. This information is subsequently used by AUTOMAPER to construct the internal chip representation and to resolve the coordinates associated with each measurement path.

\subsection{checkPositionsAutomap}
% ===========================================

Validates the measurement plan generated by AutoMapper before moving the Suruga platform. It calculates and displays the absolute \texttt{x1} and \texttt{x2} positions for each device defined in the Excel file, but it does not connect to any instrument or move any axes.

\textbf{Source code:}
\href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/checkPositionsAutomap.py}
{\texttt{checkPositionsAutomap.py}}.

\subsubsection{Workflow}

\begin{enumerate}
    \item Loads the chip layout and measurement plan from an Excel file using \texttt{automaper.load\_chip()}.

    \item Uses \texttt{origin\_x1} and \texttt{origin\_x2} as the reference origins.

    \item For each measurement, calculates the input and output offsets and the absolute positions of both arms.

    \item Displays the device, ports, and calculated positions, and waits for confirmation before displaying the next measurement.
\end{enumerate}

The absolute coordinates are calculated according to

\begin{equation}
    x_1 = \mathrm{origin}_{x1} - \mathrm{input}.x
\end{equation}

and

\begin{equation}
    x_2 = \mathrm{origin}_{x2} - \mathrm{output}.x.
\end{equation}

\subsubsection{Recommended Usage}

Run this routine whenever the Excel file, chip coupling, or origin convention changes. Compare the printed positions against the mechanical setup limits before running a routine that moves the machine.

\subsubsection{Results}

This routine does not create files or perform measurements. Its output consists of the position list displayed in the console.


% ===========================================
\subsection{moveAutomapOPM}
% ===========================================

Automatically iterates through the measurements defined by AutoMapper, positions the fibers at the input and output waveguides, performs alignment on both arms, and measures the average optical power using the optical power meter (OPM).

\textbf{Source code:}
\href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/moveAutomapOPM.py}
{\texttt{moveAutomapOPM.py}}.

\subsection{Workflow}

\begin{enumerate}
    \item Loads the measurement plan from the AutoMapper Excel file.

    \item Connects to the Suruga platform and creates controllers for \texttt{x1}, \texttt{x2}, alignment, and the power meter.

    \item Loads \texttt{origin.txt} or uses the current position as the \texttt{WG0} origin.

    \item For each device, calculates the absolute positions of both arms and moves \texttt{x1} and \texttt{x2}.

    \item Performs a \textit{flat} alignment on the left arm followed by another alignment on the right arm.

    \item Reads ten samples from the OPM, calculates their average, and displays the result in the console.

    \item Requests confirmation before continuing and, once all measurements are completed, returns to \texttt{WG0}.
\end{enumerate}

\subsection{Results}

The average optical power for each device is printed to the console. The routine does not save the measurement values to a file.

\subsection{Precautions}

The routine moves both arms and requires manual confirmation between measurements. Verify the position plan using
\href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/checkPositionsAutomap.py}{\texttt{checkPositionsAutomap}} before running it.


% ===========================================
\subsection{moveAutomapOPM\_OSA}
% ===========================================

Characterizes the devices defined by AutoMapper by combining Suruga platform
movement, automatic alignment, an average optical power measurement using the
OPM, and spectrum acquisition with the OSA.

\textbf{Source code:}
\href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/moveAutomapOPM_OSA.py}
{\texttt{moveAutomapOPM\_OSA.py}}.

\subsection{Workflow}

\begin{enumerate}
    \item Loads the chip layout and measurement plan from Excel.

    \item Connects to the Suruga platform, OPM, and OSA, and configures the
    spectral sweep.

    \item Loads or saves the \texttt{WG0} origin in \texttt{origin2.txt}.

    \item For each device and repetition, positions \texttt{x1} and
    \texttt{x2} based on the corresponding input and output waveguides.

    \item Aligns the left and right arms.

    \item Runs an OSA sweep, retrieves the trace, and averages ten power
    readings.

    \item Saves the trace along with the device, ports, optical power, and
    repetition number as metadata.

    \item Returns to \texttt{WG0} and closes the OSA connection.
\end{enumerate}

\subsection{Results}

For each device, the routine saves a trace to:

\begin{center}
\texttt{data/<date>/medicion\_<repetition>\_<device>\_<input>\_<output>.txt}
\end{center}

The file contains the spectral data and metadata including the device, ports,
average optical power, and repetition number.

\subsection{Precautions}

With \texttt{DEBUG\_MODE=True}, the routine pauses before the OSA sweep,
between devices, and before returning to the origin.

Before using automatic mode, validate the movements with
\href{https://github.com/niospinamev2/SurugaSeikiHex/blob/main/rutinas/checkPositionsAutomap.py}
{\texttt{checkPositionsAutomap}}, verify the origin, and confirm that the OSA
VISA resource is available.
